# CHANGELOG — BOTVEX Order Bot v4

## Изменения

- Добавлена отдельная таблица `admin_ui_state` и хранилище текущей панели администратора; повторный `/admin` и несколько разделов переиспользуют прежний экран, когда это возможно.
- Добавлен метод поиска клиентского уведомления по владельцу и `message_id`.
- Централизована фиксация панели: когда уведомление превращается в обычный экран, его запись помечается обработанной; вновь доставленное уведомление защищено от преждевременной очистки.
- При открытии уведомления клиента сначала успешно обновляется панель заказа и только затем уведомление отмечается обработанным. При переходе из уведомления очищается состояние FSM, а сохранённый черновик остаётся в SQLite.
- Невалидный текст формы клиента отображается в текущей панели вместо создания отдельного ответа.
- Убраны повторные ранние попытки удаления входного текста из FSM-обработчиков; общий middleware удаляет приватное входящее сообщение после успешного завершения обработчика.
- Неавторизованный `/admin` обрабатывается молча; общий middleware пытается удалить входную команду.
- Поиск заявок администратора, назначение цены и внутренняя заметка используют текущую панель вместо цепочки служебных сообщений.
- `/stats`, `/orders` и повтор доставки уведомлений используют отслеживаемую панель администратора.
- Добавлены тесты для хранения админ-панели, безопасного поиска уведомления по `message_id`, синхронизации всех ключевых клиентских экранов, централизованной очистки входящих сообщений, сохранения новых уведомлений и порядка перехода в карточку.

## Совместимость и безопасность

- Существующие таблицы и заказы не удаляются; таблица панели администратора добавляется идемпотентно.
- `.env`, реальная база данных, секреты, виртуальное окружение и пользовательские данные не включены в архив.
- Удаление сообщений остаётся best-effort и зависит от возможностей Telegram API.
