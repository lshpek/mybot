# BOTVEX Order Bot v4

Telegram-бот для приёма и сопровождения заказов на Python-разработку, Telegram-ботов, автоматизацию, API и AI-интеграции.

## Что изменено в v4

- **Единая клиентская панель.** Главное меню, каталог, форма, карточка заявки и уведомления используют один отслеживаемый `message_id` там, где Telegram разрешает редактирование. Все ключевые клиентские экраны синхронизируют ссылку на панель. После замены уведомления обычным экраном ссылка на старое уведомление помечается обработанной, чтобы последующая очистка не удалила уже обновлённую панель.
- **Временные уведомления.** Статусы, цены, запросы уточнения и ответы разработчика проходят через общий механизм клиентских уведомлений. Уведомление открывает связанную заявку; после успешного перехода оно превращается в целевую карточку, а в базе отмечается обработанным. Если редактирование невозможно, используется ограниченный fallback.
- **Одна админ-панель.** Ссылка на административную панель хранится в SQLite отдельно от клиентской. Повторный `/admin`, поиск, статистика и списки стараются обновлять существующее сообщение вместо создания новой цепочки панелей.
- **Очистка входящих сообщений.** Общий middleware пытается удалить входящие сообщения приватного чата после успешного завершения обработчика. Данные формы сохраняются до удаления. Для обычного пользователя `/admin` не создаёт ответного сообщения; входная команда удаляется тем же middleware.
- **Уточнения.** Администратор создаёт вопрос с предпросмотром и подтверждением; клиент может ответить только на активный запрос. Ответ связывается с конкретной заявкой, сохраняется в истории и закрывает запрос.
- **Карточка заявки.** Хронология доступна прямо в карточке клиента; отдельная клиентская кнопка истории отсутствует. Внутренние заметки клиенту не показываются.
- **Каталог и цена.** Используются реальные данные `config/services.json`; назначение цены валидируется и сохраняется в истории.
- **Миграция SQLite.** Добавлена отдельная таблица `admin_ui_state` и метод поиска уведомления по владельцу и `message_id`. Инициализация идемпотентна, старые заявки и их идентификаторы сохраняются.
- **Безопасность.** Проверки `ADMIN_IDS`, владение клиентской заявкой, состояние уведомления и статус запроса уточнения перепроверяются в обработчиках.

## Требования

- Windows 11
- Python 3.12
- aiogram 3 — зависимость указана в `requirements.txt`
- Telegram bot token и числовой Telegram user ID в `ADMIN_IDS`

## Настройка `.env`

Для новой установки скопируй шаблон, только если `.env` ещё не существует:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

Обязательно заполни `BOT_TOKEN` и `ADMIN_IDS`. Не копируй `.env.example` поверх существующего `.env`.

Основные параметры: `BOT_TOKEN`, `ADMIN_IDS`, `BUSINESS_NAME`, `DB_PATH`, `TIMEZONE`, `DEVELOPER_USERNAME`, `SERVICES_FILE`, необязательный `GITHUB_URL`, `CURRENCY`.

## Установка с нуля

Распакуй `BOTVEX_order_bot_v4.zip` так, чтобы на диске появилась папка `BOTVEX_order_bot_v4`. Открой PowerShell в этой папке:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
.\.venv\Scripts\python.exe -m compileall -q bot.py app tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe bot.py
```

Заполняй `.env` до запуска бота. Для автотестов реальный `BOT_TOKEN` не нужен.

## Обновление существующей установки

1. Останови текущего бота сочетанием `Ctrl+C`.
2. Скачай и распакуй `BOTVEX_order_bot_v4.zip` на рабочий стол. Итоговый путь должен быть `C:\Users\1\Desktop\BOTVEX_order_bot_v4`.
3. Выполни в PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
& "$env:USERPROFILE\Desktop\BOTVEX_order_bot_v4\update_botvex.ps1" `
  -TargetPath "C:\Users\1\Desktop\BOTVEX_order_bot"
```

4. Когда скрипт запросит подтверждение, введи `STOP` заглавными буквами.
5. Дождись сообщения об успешном обновлении. Если любой тест или миграция не прошли, не запускай новую версию.

Скрипт создаёт резервную копию в `C:\Users\1\Desktop\BOTVEX_backups`, сохраняет `.env`, виртуальное окружение, SQLite и существующий `config/services.json`. При ошибке он прекращает работу и пытается восстановить прежний проект. Не удаляй резервные копии.

## Проверка и запуск после обновления

```powershell
Set-Location "C:\Users\1\Desktop\BOTVEX_order_bot"
.\.venv\Scripts\python.exe -m compileall -q bot.py app tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe bot.py
```

Не закрывай терминал, пока бот работает. Для остановки нажми `Ctrl+C`.

## Проверки в Telegram

1. Выполни `/start` несколько раз и проверь, что не скапливаются одинаковые панели.
2. С обычного аккаунта отправь `/admin`: текстового отказа быть не должно; команда удаляется по возможности.
3. Создай заявку; проверь, что форма переиспользует панель, а отправленные ответы удаляются после обработки.
4. Администратор меняет статус: клиентская панель заменяется уведомлением.
5. Нажми «Открыть заявку»: уведомление должно превратиться в связанную карточку, а не оставаться отдельным активным уведомлением.
6. Запроси уточнение, ответь клиентом и проверь историю.
7. Назначь цену и проверь аналогичный цикл уведомления.
8. Повтори сценарии на телефоне и Telegram Desktop.

## Ограничения и непроверенные сценарии

- Удаление сообщений — best-effort: Telegram API не разрешает удаление произвольного сообщения во всех ситуациях. При отказе бот использует fallback, но абсолютную очистку гарантировать нельзя.
- В этой сборочной среде нет установленного `aiogram` и доступного подключения к Telegram API; реальный запуск с токеном, удаление сообщений на Android/iOS/Desktop и совместимость PowerShell 5.1 необходимо проверить на целевой Windows-машине.
- FSM активной сессии использует `MemoryStorage`; черновик сохраняется в SQLite. После перезапуска проверь восстановление через `/start`.
